# Kerbecs Validation Plan

This document outlines a comprehensive, HPC-grade testing strategy for the Kerbecs concurrent AddressSanitizer. To achieve exhaustive coverage (~1000+ distinct test cases), the suite relies on a **parameterized combinatorial matrix** intersecting core mechanics with various types, layouts, alignments, and concurrency models, supplemented by discrete edge-case and violation trigger tests.

For how each test is structured in code (fixture, logger, validator, Hades config), see [`TEST_FORMAT.md`](../TEST_FORMAT.md) at the repo root.

> **Note on test counts:** The numbers in section headings (e.g. `~600 Tests`) are intent targets, not hard counts. They will drift as cases are added or removed — treat them as scale indicators only.

---

## Pass Criteria

Every test in this plan has a defined pass signal. There are three kinds:

| Kind | Mechanism | When to use |
|---|---|---|
| **State assertion** | `verify(condition, "msg")` via SVK — emits `ExceptionEntry`, triggers debug break | Lifecycle states, return values, buffer contents |
| **Violation trap** | `verify(kerbecs_last_violation() == ExpectedViolation, ...)` | Any test in Section 2 that says "Expect `ViolationName`" |
| **Soft warning** | `m_Validator.expect(condition, "msg")` — emits `LogEntry(Warning)`, no break | Non-fatal deviations, theoretical edge cases |

All Stratum output is flushed via `Orchestrator::getInstance().flush()` after the run completes. Failures appear as `ExceptionEntry` records tagged `"ValidationKit"` in the log.

## 1. Combinatorial Test Matrix (~600 Tests)

These tests validate the fundamental correctness of the `ShadowPtr` lifecycle. They are generated by iterating through the following parameter axes:

**Axes:**
- **Layout Policy (3):** `NormalLayout`, `EnhancedLayout`, `StaticLayout`
- **Payload Type (5):** `uint8_t` (1B), `float` (4B), `struct Vector4` (16B), `struct Matrix4x4 alignas(32)` (64B), `struct L2CacheBlock alignas(64)` (128B)
- **Allocation Count (4):** Single object (1), Small array (10), Large array (1024), Page-spanning array (8192)
- **Alignment Constraint (4):** Default (alignof T), AVX2 (32), AVX-512 (64), Cache-line (128)
- **Concurrency Context (2):** Single-threaded, Multi-threaded (Alloc thread $\neq$ Access thread, but Destroy thread $=$ Alloc thread)

**Tests run per combination (3 $\times$ 5 $\times$ 4 $\times$ 4 $\times$ 2 = 480 base cases):**
1. **Lifecycle:** `shadowAllocate` $\rightarrow$ `shadowConstruct` $\rightarrow$ verify state (`CONSTRUCTED`) $\rightarrow$ `shadowDestroy` $\rightarrow$ verify state (`DESTROYED`).
2. **Partial Array Init:** Allocate array, construct only even indices. Verify even indices are `CONSTRUCTED` and odd indices are `UNINITIALIZED`.
3. **Quarantine Flow:** Destroy object, advance epoch by 1 (verify `Quarantine`), advance epoch by 2, flush (verify `Dead` / wild pointer).
4. **Registry Range Check:** Perform `findRange` on the exact base pointer, the middle of the payload, and the last byte of the payload. Ensure all return the correct node.
5. **Guard Verification:** Explicitly call `shadowVerifyGuards` on a healthy block and assert `true`.

## 2. Violation Detection Suite (~200 Tests)

These tests intentionally perform illegal operations to ensure Kerbecs traps them correctly, transitions states safely, and reports exact violation metadata. Run across all 3 Layouts where applicable.

### 2.1 Spatial Violations (Buffer Overflows)
- **Leading Redzone Corruption:** Overwrite 1 byte, 4 bytes, and all bytes of the leading redzone. Call `shadowDestroy` $\rightarrow$ Expect `BufferOverflow`.
- **Trailing Redzone Corruption:** Overwrite bytes immediately following the user payload. Call `shadowDestroy` $\rightarrow$ Expect `BufferOverflow`.
- **Leading Canary Corruption (Enhanced/Static):** Corrupt the 8-byte canary word preceding the payload. Expect `BufferOverflow`.
- **Trailing Canary Corruption (Enhanced/Static):** Corrupt the trailing canary word. Expect `BufferOverflow`.
- **Underflow Access:** Read/write memory strictly before the payload offset. Expect segfault or `UseBeforeInit`/`CORRUPTED` if it hits poisoned shadow memory.

### 2.2 Temporal Violations (Use-After/Before)
- **Double Free:** `shadowDestroy` an object, then immediately call `shadowDestroy` again. Expect `DoubleFree`.
- **Use After Free (in Quarantine):** Destroy an object, then call `shadowGetMemoryState` on it before the epoch flushes it. Expect `UseAfterFree`.
- **Use Before Init:** `shadowAllocate` a block without calling `shadowConstruct`. Access state. Expect `UseBeforeInit`.
- **Stale Pointer (Dead):** Destroy an object, advance epoch, flush quarantine, then query state. Expect `WildPointer` (node is `Dead` and stripped from lookups).

### 2.3 Metadata & Structural Violations
- **Metadata Checksum Corruption (Enhanced):** Mutate `m_ThreadHash` or `m_Checksum` in the trailing `EnhancedMetaData` block. Expect `MetadataCorruption`.
- **Metadata Mirror Mismatch (Enhanced):** Mutate the leading metadata block so it no longer matches the trailing block. Expect `MetadataCorruption`.
- **Alignment Violation:** Pass a manually misaligned base pointer to `shadowConstruct` or `shadowAllocate`. Expect `AlignmentViolation`.
- **Size Overflow:** Request an allocation count where `count * sizeof(T)` overflows `size_t`. Expect graceful `false` return from `shadowAllocate` (or `SizeOverflow` trap).

### 2.4 Thread & Ownership Violations
- **Foreign Thread Free:** Thread A allocates. Thread B calls `shadowDestroy`. Expect `ThreadOwnership`.
- **Retiring Boundary Violation:** Thread A calls `shadowDestroy` (acquires `m_DtorLock`). Thread B concurrently attempts to `shadowGetMemoryState` while the block is in `Retiring` state. Expect `RetiredBoundaryViolation` (fail-fast).
- **Concurrent Destruct Race:** Thread A and Thread B simultaneously call `shadowDestroy` on the same valid pointer. One succeeds, the other fails `tryLock` and raises `ThreadOwnership` or `DoubleFree`.

## 3. Subsystem Stress & Edge Cases (~150 Tests)

### 3.1 Allocation Registry (Lock-Free Map)
- **Bucket Collision (Hash chaining):** Artificially allocate blocks with addresses tailored to hash to the same bucket (stride by `(1 << 17)`). Verify `find` traverses the linked list correctly.
- **Overlap Detection:** Manually invoke `Registry::insert` twice with the same `p_BlockBase`. The second must fail and report `OverlapDetected`.
- **Max Capacity:** Exhaust the node pool (`131,072` allocations). Ensure the 131,073rd insertion gracefully returns `false` (or traps if configured).
- **FindRange Boundaries:** `findRange` strictly 1 byte before `m_UserPtr` (returns null), exactly at `m_UserPtr` (returns node), exactly at `m_UserPtr + m_UserSize - 1` (returns node), exactly at `m_UserPtr + m_UserSize` (returns null).

### 3.2 Quarantine Queue (Ring Buffer)
- **Epoch Window Math:** Enqueue at Epoch 10. Flush at Epoch 10 (no-op), Epoch 11 (no-op), Epoch 12 (releases).
- **Ring Wrap-Around:** Enqueue and flush continuously to force `m_Head` and `m_Tail` to wrap around the `QUARANTINE_CAPACITY` ring buffer limit. Ensure slot indices wrap correctly using the modulo mask.
- **Saturation Trap:** Pause the epoch thread. Enqueue `QUARANTINE_CAPACITY` objects. Attempt to enqueue one more. Expect fail-fast `QuarantineSaturation` violation.
- **Teardown Drain:** Leave 50 objects in Quarantine across various future epochs. Call `MemoryZone::teardownShadowzone()`. Verify all objects are unconditionally flushed (`SIZE_MAX` epoch).

### 3.3 Shadow Bitmap & Virtual Memory
- **Lazy Page Commit:** Allocate an object that straddles a 4KiB page boundary (`Memory::PAGE_SIZE`). Verify the BumpAllocator commits both pages. Verify `shadowPoison` correctly handles bit-offsets across the page boundary.
- **Shadow Scale Mapping:** Manually calculate `user_addr >> 3` and verify it matches `mapToShadow`. Ensure out-of-bounds pointers map to `nullptr`.
- **Poison Granularity:** `shadowPoison` exactly 3 bytes. Verify `countPoisoned` returns exactly 3. `shadowUnpoison` 1 byte. Verify `countPoisoned` returns exactly 2.
- **Leak Detection:** Allocate an object. Do not destroy it. Call `teardownShadowzone()`. Expect `LeakDetected` violation to fire before process exit.

## 4. Static and Global Macros (~50 Tests)

- **KERBECS_PERSISTENT Lifecycle:** Define an object using `KERBECS_PERSISTENT`. Verify it allocates from `StaticAllocator` (`m_StaticZone`). Verify state is `CONSTRUCTED`. Let scope exit and ensure the generated `KerbecsDestructor` triggers `shadowDestroy`.
- **KERBECS_GLOBAL Lifecycle:** Define an object using `KERBECS_GLOBAL`. Verify it allocates from `GlobalAllocator` (`m_GlobalZone`).
- **Implicit Initialization:** Do not call `initShadowzone()`. Trigger a `KERBECS_PERSISTENT` macro. Verify the macro's internal `_KerbecsInit` struct successfully calls `initShadowzone()` safely before allocation.

---

## 5. Custom Policies & Interfaces (~20 Tests)

- **Custom Allocator Injection:** Create a mocked `AllocatorConcept` that tracks allocation/deallocation calls. Inject into `ShadowPtr`. Verify the Quarantine queue's type-erased thunk successfully routes the physical free back to the mock allocator upon epoch flush.
- **Custom Hasher:** Inject a dummy hasher that always returns `0x1234`. Verify `EnhancedMetaData` stores `0x1234` and validates it successfully on destroy.

## 6. Heavy Hitters (Extreme Stress & Concurrency) (~100 Tests)

These tests are designed to push the lock-free primitives and virtual memory management to their breaking points.

> **Implementation note:** Some entries below (marked `[theoretical]`) describe failure modes that are difficult or impossible to trigger deterministically in userspace (e.g. epoch counter wrap, interrupted CAS). These are documented for completeness but should be implemented as conditional stubs — run only when the relevant internal hook or fault-injection path exists.

### 6.1 The Thundering Herd (Registry Contention)
- **High-Frequency Bucket Hammering:** Launch 128 threads where every thread repeatedly allocates and destroys objects that hash to the *same* registry bucket. This stresses the bucket spinlock and the CAS prepend logic under maximum contention.
- **Global Counter Contention:** Massive parallel allocation/destruction to stress the atomic `m_Count` and `m_NodeCursor` in the `AllocationRegistry`.

### 6.2 Destructor Recursion & Nesting
- **Recursive Shadowing:** A shadowed object's destructor contains `ShadowPtr` handles to other shadowed objects. This tests nested `beginRetiring` calls and ensures the `m_DtorLock` and registry state machine handle recursive teardowns without deadlocking or state corruption.
- **Cyclic Dependencies:** `[theoretical]` Attempt to destroy objects with cyclic `ShadowPtr` references (if applicable) to verify the system handles the "Retiring" state correctly for the entire group.

### 6.3 Quarantine Pressure & Epoch Lag
- **Burst Enqueue / Batch Flush:** Pause the epoch thread until the quarantine is 99% full. Then, advance the epoch and trigger a massive `flushEligible` call. This validates the `m_FlushLock` efficiency and the performance of the `NodePoolSegment` scan during high-volume reclamation.
- **Epoch Overflow Simulation:** `[theoretical]` Verify the system's behavior if the 64-bit epoch counter wraps.

### 6.4 VA Boundary & Page Stress
- **Cross-Zone Straddling:** Force an allocation that attempts to straddle the boundary between the `ShadowZone` and `GlobalZone`. Verify the mapping logic correctly identifies the OOB access or traps.
- **Interleaved Page Commits:** Multiple threads simultaneously allocating objects that land on the same 4KiB page. This tests the thread-safety and idempotency of `Memory::commitPageIfNeeded` across racing threads.

### 6.5 Signal & Interrupt Resilience
- **Interrupted CAS:** `[theoretical]` Simulate a context switch or software interrupt during the window between a registry node's state becoming `Retiring` and its `m_DtorLock` being acquired. Ensure no node is left in an orphaned or inconsistent state.
- **NUMA-Aware Access:** `[theoretical]` On multi-socket systems, allocate memory on Node 0 and attempt high-frequency access/destruction from threads pinned to Node 1. This validates the NUMA-neutrality of the shadow bitmap mapping.
